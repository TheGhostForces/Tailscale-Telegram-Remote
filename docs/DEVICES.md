# Добавление и удаление устройств

В системе два вида клиентов:

| Вид | Что ставится | Управление через Telegram-бота |
|---|---|---|
| **Компьютер** (Windows / Linux) | Tailscale + RustDesk + агент | да |
| **Телефон** и другие клиенты только для RustDesk | Tailscale + RustDesk | **нет**, в боте не появляются |

Список устройств бота хранится в `/opt/rc-bot/devices.yaml` и ведётся командой `rcctl` на VPS. Бот перечитывает файл сам в течение нескольких секунд, перезапуск не нужен (принудительно: `/reload` в боте). О каждом изменении списка бот присылает уведомление.

Все команды `rcctl` выполняются на VPS через `sudo`. Подсказка по всем: `sudo rcctl --help`.

---

## Добавить компьютер

**1. На новом компьютере** установите Tailscale и войдите в **тот же аккаунт** (тег не нужен: ACL уже разрешает боту доступ ко всем вашим устройствам на порт агента). Узнайте адрес: `tailscale ip -4`. Установите RustDesk и укажите ваш сервер и ключ (как на остальных устройствах).

**2. На VPS** зарегистрируйте устройство:
```bash
sudo rcctl add pc2 --address 100.x.y.z --mac AA:BB:CC:DD:EE:FF --title "Рабочий ПК"
```
- `pc2`: короткое имя (латиница, цифры, дефис), под ним устройство видно в боте;
- `--address`: Tailscale-адрес из шага 1. Можно указать имя устройства из `tailscale status`, тогда адрес определится сам;
- `--mac`: нужен для Wake-on-LAN. Без него устройство добавится без пробуждения;
- `--wake-host`: белый IP или DDNS роутера. Не нужен, если уже есть устройства с пробуждением через роутер: берётся тот же. Вместо него можно указать `--wake-via pc`: тогда устройство будится по LAN через уже включённый `pc`;
- внешний UDP-порт для пробуждения подбирается автоматически (следующий свободный после `40009`).

Команда выведет секрет и готовые команды установки с ним.

**3. На новом компьютере** установите агента (папка `agent/` из репозитория), подставив секрет из вывода `rcctl`:
- Windows, PowerShell от администратора:
  ```powershell
  powershell -ExecutionPolicy Bypass -File .\install-windows.ps1 -Secret <СЕКРЕТ> -ConfigureWol
  ```
- Debian/Linux, обычный пользователь:
  ```bash
  bash install-linux.sh --secret <СЕКРЕТ> --wol <ИНТЕРФЕЙС>
  ```

**4. Для пробуждения** на роутере: резерв DHCP и ARP-привязка для MAC этого компьютера, виртуальный сервер UDP: внешний порт (его показал `rcctl`) → внутренний IP, порт 9. WoL в BIOS/UEFI.

**5. Проверка:**
```bash
sudo rcctl list --check      # агент нового устройства должен быть «онлайн»
```
В боте: `/devices`, `/status pc2`.

## Добавить телефон (только RustDesk)

На телефоне установите Tailscale (тот же аккаунт) и RustDesk, укажите ваш сервер и ключ. Всё: в `rcctl` и в бот ничего добавлять не нужно, и управление телефоном через бота не предусмотрено.

Если хотите вести учёт, чтобы не забыть про устройство при удалении:
```bash
sudo rcctl add-client pixel --title "Телефон" --note "Pixel 8"
```
Такая запись видна только в `rcctl list`, в боте её нет.

## Убрать устройство

```bash
sudo rcctl remove pc2        # компьютер или клиент; спросит подтверждение (-y без вопроса)
```
Это убирает устройство из бота, но **не отзывает доступ**. Завершите:
1. **Tailscale admin console → Machines → устройство → Remove.** Это настоящий отзыв: после него устройство не видит вашу сеть.
2. На самом компьютере удалите агента: `uninstall-windows.ps1` (PowerShell от администратора) или `bash uninstall-linux.sh`.
3. На роутере удалите проброс UDP-порта, резерв DHCP и ARP-привязку.
4. Удалите RustDesk на устройстве. RustDesk-сервер список клиентов не хранит. Если устройство потеряно или украдено, смените постоянные пароли RustDesk на остальных устройствах.

## Другие команды
| Команда | Что делает |
|---|---|
| `sudo rcctl list [--check]` | список устройств; `--check` показывает, отвечают ли агенты |
| `sudo rcctl show NAME` | параметры устройства и команды установки (с секретом) |
| `sudo rcctl rotate NAME` | новый секрет агента, например при подозрении на утечку; затем повторите установку на устройстве с новым `-Secret` |
| `sudo rcctl migrate` | перенести устройства из старого `config.yaml` + `.env` в `devices.yaml` (разово, см. ниже) |

## Переход со старой схемы
Если устройства у вас описаны в `config.yaml` бота, а их секреты в `.env`, выполните один раз:
```bash
cd /opt/rc-bot
sudo rcctl migrate
sudo rcctl list --check
```
Бот переключится на `devices.yaml`. После этого блок `devices` в `config.yaml` и переменные `PC_SECRET`/`LAPTOP_SECRET` в `.env` можно удалить.

## Файл `devices.yaml`
Содержит секреты агентов (права `600`, владелец `rcbot`), в git не добавляется (см. `.gitignore`). Пример структуры: `bot/devices.example.yaml`. Вручную его править можно, но безопаснее через `rcctl`: он проверяет имена, MAC и адреса и записывает файл атомарно.
