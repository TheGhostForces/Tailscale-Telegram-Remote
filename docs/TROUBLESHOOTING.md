# Разбор проблем

Всё ниже уже встречалось при реальной установке.

## Windows

**Установщик: «The string is missing the terminator» и «кракозябры» вместо текста**
Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI. `install-windows.ps1` намеренно написан только латиницей; не добавляйте в него кириллицу.

**Задача `RC-Agent` в состоянии `Ready`, порт 8765 не слушается**
Агент завершился. Запустите вручную и смотрите ошибку:
```powershell
Stop-ScheduledTask -TaskName RC-Agent
cd $env:LOCALAPPDATA\rc-agent
.\venv\Scripts\python.exe agent.py
```
Ошибки при запуске из `pythonw.exe` пишутся в `agent.log` и `agent-error.log` рядом с агентом (в `agent.py` предусмотрена подмена `stdout/stderr`, у `pythonw` их нет). Код завершения: `Get-ScheduledTaskInfo -TaskName RC-Agent`.

**Повторная установка вернула старую версию**
Установщик копирует `agent.py` из своей папки в `%LOCALAPPDATA%\rc-agent`. Держите в папке установщика актуальный `agent.py`.

## Проверка связи агента с VPS

| Результат | Причина |
|---|---|
| JSON со статусом | всё работает |
| `HTTP 401` | неверный секрет или расхождение часов больше 30 с |
| `HTTP 403` | запрос не из сети Tailscale (100.64.0.0/10) |
| таймаут | агент не запущен, нет связи по Tailscale, режет ACL или файрвол |

Для таймаута: `tailscale ping <адрес>` и `nc -vz -w 5 <адрес> 8765` на VPS; на устройстве `netstat -ano | findstr 8765` (Windows) или `ss -ltn | grep 8765` (Linux). Полнотуннельный VPN-клиент на устройстве может перехватывать трафик Tailscale.

## Tailscale

- Тег `tag:bot` должен существовать до создания auth-ключа и до применения ACL.
- ACL заменяет политику целиком (раздел Access controls → JSON editor). Правила проверяются на вкладке Tests.

## VPS

- **Docker обходит ufw.** Порты, опубликованные контейнерами (`ports:`), доступны из интернета независимо от правил ufw. Контейнеры RustDesk используют `network_mode: host`, на них ufw действует.
- `vps-firewall.sh` делает `ufw reset`: перед запуском проверьте вход по SSH-ключу и номер порта SSH.
- `install-vps.sh` копирует файлы бота в `/opt/rc-bot`. Файлы `.env` и `config.yaml` заполняются вручную, затем `chown rcbot:rcbot` и `chmod 600 .env`.

## Бот

- В `journalctl -u rc-bot` сообщения вида «... не задан» означают пустое значение в `.env`.
- Бот молчит на `/start`: неверный `OWNER_ID`. Попытки доступа с чужих ID приходят уведомлением на ID из конфига.
- Устройство в статусе «не в сети», хотя агент работает: проверьте адрес и порт в `config.yaml` бота и секрет (`*_SECRET`).
- Кнопки внизу не обновились после обновления бота: отправьте `/menu`.
- Нажатия кнопок остаются в чате: бот может удалять сообщения пользователя только в личном чате и в течение 48 часов; проверьте `cleanup_user_messages` в `config.yaml`.
- Время в таймерах и журнале отличается от вашего: задайте `timezone` в `config.yaml` (например, `Europe/Moscow`).
